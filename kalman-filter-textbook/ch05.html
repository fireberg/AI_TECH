第五章：实战——无人机水平位置估计

完整 2D 卡尔曼滤波器：IMU + GPS 融合，从代码到可视化

本章目标

  • 构建一个完整的 4 维卡尔曼滤波器（[x, y, vx, vy]）
  • 模拟真实的无人机圆形轨迹飞行，融合 IMU 加速度和 GPS 位置
  • 实时调参并观察滤波效果，体验 Q/R 调参的手感

一、系统设定

我们模拟一架无人机沿椭圆/圆形轨迹飞行：

  • 状态：\(\mathbf{x} = [x, y, v_x, v_y]^T\)
  • IMU 输入：加速度 \([a_x, a_y]\)，采样率 50Hz，含噪声和偏差
  • GPS 测量：位置 \([x_{gps}, y_{gps}]\)，采样率 5Hz，标准差约 3m
  • 关键差异：IMU 每步都有，GPS 每 10 步才来一次
$$\mathbf{F} = \begin{bmatrix}1&0&\Delta t&0\\0&1&0&\Delta t\\0&0&1&0\\0&0&0&1\end{bmatrix}, \quad \mathbf{B} = \begin{bmatrix}\frac{\Delta t^2}{2}&0\\0&\frac{\Delta t^2}{2}\\\Delta t&0\\0&\Delta t\end{bmatrix}, \quad \mathbf{H} = \begin{bmatrix}1&0&0&0\\0&1&0&0\end{bmatrix}$$

    x: [0, 0, 0, 0],

    B: [[.5*dt*dt,0],[0,.5*dt*dt],[dt,0],[0,dt]],
    H: [[1,0,0,0],[0,1,0,0]],
    Q: buildQ(dt, q),
    R: [[r, 0],[0, r]],

    predict: function(ax, ay) {
      /* ① x = F*x + B*u */

二·五、互补滤波器——穷人版卡尔曼

在看完上面那一大段 KF 代码后，你可能会想：有没有更简单的方案？当然有——互补滤波器（Complementary Filter），它本质上就是第四章讲的稳态卡尔曼滤波器的特殊形式。

对于位置估计，一个互补滤波器可以写成一行：

$$\hat{x}_k = \alpha \cdot x_{GPS} + (1-\alpha) \cdot (\hat{x}_{k-1} + v \cdot \Delta t)$$

这里的 \(\alpha\) 就对应于稳态卡尔曼增益 \(\mathbf{K}_\infty\)。当 GPS 噪声大（R 大）时，\(\alpha\) 小，更相信惯性推算；当 GPS 噪声小（R 小）时，\(\alpha\) 大，更相信 GPS。

/* 互补滤波器——3 行 C 代码，效果出奇地好 */
float comp_filter(float gps_pos, float accel, float dt) {
    static float pos = 0, vel = 0;
    vel += accel * dt;
    pos = 0.98f * (pos + vel * dt) + 0.02f * gps_pos;
    return pos;
}

对比卡尔曼滤波器：

互补滤波器 卡尔曼滤波器

自适应噪声不能自动适应

在姿态估计领域，Madgwick 滤波器和 Mahony 滤波器都是互补滤波器的变体——它们在四元数空间上做类似的高通/低通融合。之所以效果好，是因为陀螺仪和加速度计的噪声特性相对稳定，不太需要自适应。

但一旦你需要融合多个传感器（GPS + 气压计 + 光流 + ...）、需要知道估计的不确定度（用于决策）、或者噪声特性会变化——就该用完整的卡尔曼滤波器了。

三·五、马氏距离门限——别让坏数据毁了你的滤波器

在真实飞行中，GPS 偶尔会给出严重错误的读数——比如在城市峡谷中信号反射（multipath），位置突然跳几十米。如果你把这种"毒数据"直接喂给卡尔曼滤波器，它会被猛烈拉偏，可能需要好几秒才能恢复。

解决方法：在做 KF 更新之前，先检查新息是否"合理"。用马氏距离（Mahalanobis Distance）来判断：

$$d^2 = \boldsymbol{\nu}^T \mathbf{S}^{-1} \boldsymbol{\nu}$$

其中 \(\boldsymbol{\nu}\) 是新息，\(\mathbf{S} = \mathbf{H}\mathbf{P}\mathbf{H}^T + \mathbf{R}\) 是新息的期望协方差。如果滤波器正确调谐，\(d^2\) 服从 \(\chi^2(m)\) 分布。

设定一个门限：如果 \(d^2\) 超过 \(\chi^2\) 分布的 99% 分位数，就拒绝这次测量——它几乎肯定是异常值。

/* 马氏距离门限检测——在 KF update 前调用 */
/* 对于 m=2 的 GPS 测量 */
float innov[2] = { gps_x - kf.x[0], gps_y - kf.x[1] };

/* Si 是 S 的逆矩阵（在计算 K 时已经算过了，直接复用） */
float d2 = innov[0]*Si[0][0]*innov[0] + innov[1]*Si[1][1]*innov[1]
         + 2*innov[0]*Si[0][1]*innov[1];

if (d2 > 9.21f) {
    /* 拒绝这次 GPS 测量——可能是多径效应 */
    log_warning("GPS innovation gate reject: d2=%.1f", d2);
    return;  /* 跳过更新，继续预测 */
}

/* 通过门限检测，正常执行 KF update */
kf2d_update(&kf, gps_x, gps_y);

关键原则：拒绝异常值后，不要重置滤波器——直接跳过更新步，让预测继续运行。滤波器会用惯性推算撑过没有 GPS 的时段，等下一次正常的 GPS 数据到来再校正。PX4 和 ArduPilot 的 EKF 都实现了这种新息门限检测（innovation gate test），对每个传感器的每次更新都会做。

嵌入式开发者笔记

异步更新——飞控中的关键设计

在真实飞控中，IMU 跑 100~400Hz，GPS 只有 1~10Hz。代码结构应该是这样的：

/* 主循环伪代码 (典型飞控架构) */
void main_loop(void) {  /* 400Hz tick */
    imu_read(&ax, &ay, &az);

    /* 每次 tick 都做预测 */
    kf2d_predict(&kf, ax, ay);

    /* 只有 GPS 数据到来时才做更新 */
    if (gps_data_ready()) {
        gps_read(&gps_x, &gps_y);
        kf2d_update(&kf, gps_x, gps_y);
        gps_clear_flag();
    }

    /* 输出融合后的位置和速度 */
    nav_output.x  = kf.x[0];
    nav_output.y  = kf.x[1];
    nav_output.vx = kf.x[2];
    nav_output.vy = kf.x[3];
}

dt 的处理：如果 IMU 和主循环不完全同步，最好用实际时间差 dt 来构建 F 和 B 矩阵，而不是用固定的标称值。在 STM32 上可以用 DWT 周期计数器或 TIM 定时器来获取精确的 dt。

数值检查：每次更新后，检查 P 的对角元素是否全部为正。如果出现负值，说明滤波器已经发散了——这通常意味着 Q 设得太小或者观测模型有误。

真实飞控架构参考：PX4 的 ECL-EKF（Estimation and Control Library）使用 24 维状态向量：

  • 四元数 (4) + 速度 (3) + 位置 (3) + 陀螺偏差 (3) + 加速度偏差 (3) + 地磁场 (3) + 风速 (2) + 磁偏差 (3)
  • 运行频率：IMU 预测 250Hz + 按需更新（GPS 10Hz，气压 50Hz，磁力 50Hz）
  • 使用 Joseph 形式更新 P，Mahalanobis 门限剔除异常值
  • 源码：github.com/PX4/PX4-ECL

ArduPilot 的 EKF3 架构类似，但有一个独特设计：它运行三个并行的 EKF 实例（每个 IMU 一个），通过比较各实例的归一化新息平方（NIS）来选择最佳的那个。如果某个 IMU 出了故障，对应的 EKF 实例的 NIS 会飙高，系统自动切换到健康的实例——这就是传感器冗余+滤波器冗余的双重保障。
