第一章：从振动噪声说起

为什么需要卡尔曼滤波？——从传感器噪声到智能融合的必经之路

本章目标

  • 理解传感器噪声的来源和危害（加速度计漂移、GPS 随机误差）
  • 体验简单滤波方法（均值滤波、指数滑动平均）的局限性
  • 建立"模型预测 vs 测量值"的核心矛盾意识

一、无人机上的传感器困境

假设你正在开发一架小型四旋翼无人机的飞控系统。你需要知道无人机在水平面内的位置，但你手上的传感器各有各的毛病：

加速度计（IMU）：采样率很高（100~1000Hz），但数据里掺杂着电机振动、温漂和零偏。如果你对加速度做二次积分来求位置，误差会随时间的平方增长——几秒钟就飞到天上去了（字面意思）。

GPS：直接给出位置，不会漂移，但更新慢（1~10Hz），而且有几米的随机噪声。你的无人机可能已经飞出去两米了，GPS 还在报上一个位置。

这就是我们面对的核心问题：没有一个传感器是完美的，但我们能不能把它们的优势结合起来？

一个直觉类比：两台秤称体重

在正式讨论滤波器之前，先来看一个 MIT 课程（16.322 Stochastic Estimation and Control）中经典的直觉类比，它能帮你秒懂卡尔曼滤波的核心思想。

假设你要称体重，手头有两台秤：

  • 浴室电子秤（便宜，噪声大）：显示 70.5 kg，标准差 \(\sigma_1 = 2\) kg
  • 医院体检秤（精确，但读数慢）：显示 68.2 kg，标准差 \(\sigma_2 = 0.5\) kg

你该相信哪台？答案是：都不要 100% 相信，而是做加权平均。直觉告诉我们应该更相信精度高的那台。但"更相信多少"有一个数学上的最优解。

最优的加权系数为：

$$w = \frac{\sigma_2^2}{\sigma_1^2 + \sigma_2^2} = \frac{0.25}{4 + 0.25} = 0.0588$$

最优融合结果：

$$\hat{x} = w \cdot x_1 + (1-w) \cdot x_2 = 0.059 \times 70.5 + 0.941 \times 68.2 \approx 68.34 \text{ kg}$$

注意，结果非常接近精确的那台秤——这完全符合直觉。而这个 \(w\)，就是一维卡尔曼增益。

MIT 16.322 把这叫做最小方差无偏估计（Minimum Variance Unbiased Estimation, MVUE）。融合后的方差为：

$$\sigma_{融合}^2 = \frac{\sigma_1^2 \cdot \sigma_2^2}{\sigma_1^2 + \sigma_2^2} = \frac{4 \times 0.25}{4.25} \approx 0.235 \text{ kg}^2$$

融合后的标准差约 0.49 kg——比两台秤中最好的那台（0.5 kg）还要好！这不是魔法，这是信息叠加的必然结果。卡尔曼滤波只不过是把这个简单的道理推广到了多维、动态、递归的场景。

二、先试试最直觉的办法

学过信号处理的同学可能会说："加个滤波器不就行了？"好，我们来试试。

均值滤波（Moving Average）

取最近 \(N\) 个采样的算术平均。公式很简单：

$$\hat{x}_k = \frac{1}{N}\sum_{i=0}^{N-1} x_{k-i}$$

问题是：窗口太小，噪声压不下去；窗口太大，信号被拖得面目全非，而且需要存 \(N\) 个历史值——在只有几 KB RAM 的 MCU 上，这很奢侈。

指数滑动平均（EMA / 低通滤波）

只存一个上一次的滤波值，每次做加权平均：

$$\hat{x}_k = \alpha \cdot z_k + (1-\alpha) \cdot \hat{x}_{k-1}$$

其中 \(\alpha \in (0,1)\) 是平滑系数。\(\alpha\) 越小越平滑，但相位滞后越严重。在飞控里，200ms 的滞后足以让无人机撞墙。

三、为什么简单滤波不够？

通过上面的实验，你应该注意到几个关键问题：

  1. 延迟：无论均值还是 EMA，滤波越激进，信号延迟越大。在实时控制中，这意味着你看到的是"过去的世界"。
  2. 没有"预测"能力：这些滤波器只是被动地处理观测数据，完全不知道系统的物理规律（比如"位置 = 上一次位置 + 速度 × 时间"）。
  3. 不区分信源：所有数据被一视同仁，但实际上 GPS 和 IMU 的可靠程度不同，在不同场景下应该"更相信"不同的传感器。

这就引出了一个核心问题：

我有一个物理模型的预测值，也有一个传感器的测量值，
它们都不完美——我该相信谁、相信多少？

卡尔曼滤波的回答是：谁更靠谱就更相信谁，而且靠谱程度可以用方差来量化。下一章我们会看到，它如何用一个优雅的数学框架回答这个问题。

为什么是递归的？——从最小二乘到卡尔曼

假设你有 1000 个 GPS 测量点，想估计无人机的轨迹。最直接的方法是批处理最小二乘：把 1000 个方程列出来，一次性解一个超大的矩阵方程。在 MATLAB 里这很自然，但在嵌入式系统里——你的 MCU 可能只有 64KB RAM，根本存不下所有历史数据。

更聪明的做法是递归最小二乘（Recursive Least Squares, RLS）：每来一个新测量，就更新一次估计，然后丢掉原始数据。只需要存当前的估计值和一个协方差矩阵——内存消耗是常数。

卡尔曼滤波 = 递归最小二乘 + 动态模型（状态转移方程）。这是 MIT 课程反复强调的关键洞察：

卡尔曼滤波不是"又一个滤波器"——它是一个最优递归状态估计器。

方法 数据需求 内存 有动态模型？
批处理最小二乘 所有历史数据 O(N) 否
递归最小二乘 只需当前测量 O(n²) 否
卡尔曼滤波 只需当前测量 O(n²) 是！

在嵌入式系统中，递归不是一种"可选的优化"——它是唯一可行的方案。你的 STM32 没有能力存储和回溯所有历史测量值。卡尔曼滤波的递归结构天然契合嵌入式系统的约束：固定内存、逐个处理、实时输出。

四、加速度二次积分的灾难

为了更直观地理解"为什么不能只用 IMU"，来看加速度二次积分求位置的误差增长。假设加速度计有一个恒定偏差 \(b\)（零偏）：

$$x_{err}(t) = \frac{1}{2} b \cdot t^2$$

即使 \(b\) 只有 0.01 m/s²（这在 MEMS 传感器中很常见），10 秒后位置误差就达到 0.5 米，100 秒后达到 50 米。这就是所谓的积分漂移。

五、GPS 噪声长什么样？

而 GPS 的问题恰好相反：它不会漂移（长期均值是对的），但每个测量点都有几米的随机误差。这个噪声大致符合高斯分布，标准差通常在 1~5 米（民用单频 GPS）。

有意思的是，IMU 和 GPS 的误差特性恰好互补：

  • IMU：短期准、长期飘 → 高频信息可靠
  • GPS：短期吵、长期准 → 低频信息可靠

卡尔曼滤波器本质上就是一个最优的融合器，把两个传感器的优势结合起来。我们在第五章会完整实现它。

嵌入式开发者笔记

均值滤波的内存代价：一个 N=64 窗口的 float32 均值滤波器需要 256 字节的环形缓冲区。在 STM32F103（只有 20KB SRAM）上，如果你对 6 轴 IMU 都做滤波，就要消耗近 1.5KB——这在小型 MCU 上是不可接受的。

低通滤波的相位滞后：一阶 IIR 低通滤波器（即 EMA）在截止频率处有 45° 的相位滞后。对于 100Hz 采样、10Hz 截止的典型飞控配置，这意味着大约 25ms 的延迟。如果控制回路带宽接近 10Hz，这个滞后可能导致振荡。

工程中的常见做法：IMU 数据先过一个简单的低通滤波去掉电机振动（通常切在 30~80Hz），然后送进卡尔曼滤波器。卡尔曼滤波不是要取代简单滤波，而是在简单滤波的基础上做多传感器融合。

真实飞控中的 EKF：PX4 和 ArduPilot 这两大开源飞控都使用扩展卡尔曼滤波（EKF）作为核心导航方案，而不是简单的互补滤波。ArduPilot 的 EKF3 在 STM32H7（Cortex-M7, 480MHz）上以 400Hz 运行，同时融合 3 个 IMU + 2 个 GPS + 磁力计 + 气压计的数据。为什么需要这么复杂？因为简单的滤波器无法处理异构传感器融合——不同传感器有不同的采样率（IMU 1kHz vs GPS 10Hz）、不同的噪声特性、不同的延迟，只有卡尔曼滤波框架能优雅地统一处理这些差异。

/* 嵌入式 C：一阶 IIR 低通滤波 —— 最省资源的预滤波 */
typedef struct {
    float out;    /* 上一次输出 */
    float alpha;  /* 平滑系数, 0 < alpha < 1 */
} LPF_t;

static inline float lpf_update(LPF_t *f, float in) {
    f->out += f->alpha * (in - f->out);
    return f->out;
}

第二章：系统是台机器——状态空间建模

用矩阵描述物理世界：状态转移、观测模型、噪声来源

本章目标

  • 理解状态向量、状态转移矩阵 F、输入矩阵 B、观测矩阵 H
  • 知道过程噪声 Q 和测量噪声 R 的物理来源
  • 能用状态空间方程描述"无人机在平面上运动"的场景

一、状态——系统的"内心独白"

在卡尔曼滤波的世界里，所有东西都被抽象成一个状态向量。状态不一定是你能直接测量到的，它是系统"真正的内部信息"。

比如一架无人机在一维上运动，我们关心它的位置 \(x\) 和速度 \(v\)：

$$\mathbf{x} = \begin{bmatrix} x \\ v \end{bmatrix}$$

如果你还想估计加速度计的偏差 \(b\)（零偏），状态可以扩展为：

$$\mathbf{x} = \begin{bmatrix} x \\ v \\ b \end{bmatrix}$$

状态向量的选择是一门艺术——放太少，滤波器看不到重要的动态；放太多，矩阵变大，计算量暴增。

二、状态转移方程——"下一秒会怎样？"

物理告诉我们，如果没有外力，一个匀速运动的物体在 \(\Delta t\) 后的位置和速度是：

$$x_{k+1} = x_k + v_k \cdot \Delta t$$ $$v_{k+1} = v_k$$

写成矩阵形式就是：

$$\mathbf{x}_{k+1} = \mathbf{F} \cdot \mathbf{x}_k = \begin{bmatrix} 1 & \Delta t \\ 0 & 1 \end{bmatrix} \begin{bmatrix} x_k \\ v_k \end{bmatrix}$$

这个 \(\mathbf{F}\) 就是状态转移矩阵（State Transition Matrix）。它编码了系统的物理规律。

加入控制输入

如果无人机有一个加速度输入 \(a\)（来自 IMU 测量），状态方程变成：

$$\mathbf{x}_{k+1} = \mathbf{F} \cdot \mathbf{x}_k + \mathbf{B} \cdot u_k$$

其中：

$$\mathbf{B} = \begin{bmatrix} \frac{1}{2}\Delta t^2 \\ \Delta t \end{bmatrix}, \quad u_k = a_k$$

这就是高中物理的运动方程 \(x = x_0 + v_0 t + \frac{1}{2}at^2\)，只不过写成了矩阵的样子。

从连续时间到离散时间——工程中的第一步

物理学家喜欢用连续时间描述系统——微分方程既优雅又精确：

$$\dot{\mathbf{x}} = \mathbf{A}\mathbf{x} + \mathbf{B}u$$

但你的 MCU 不会微积分。它只能在离散的时刻（每隔 \(\Delta t\)）读一次传感器、算一次。所以工程实践中的第一步是把连续模型离散化：

$$\mathbf{F} = e^{\mathbf{A}\Delta t} \approx \mathbf{I} + \mathbf{A}\Delta t + \frac{(\mathbf{A}\Delta t)^2}{2!} + \cdots$$

这是矩阵指数（matrix exponential）的泰勒展开。在大多数嵌入式场景下，\(\Delta t\) 很小（1~10ms），只取前两项就够了：

$$\mathbf{F} \approx \mathbf{I} + \mathbf{A}\Delta t \quad \text{（一阶近似）}$$

来看一个好消息：对于匀速运动模型，连续时间矩阵是：

$$\mathbf{A} = \begin{bmatrix} 0 & 1 \\ 0 & 0 \end{bmatrix}$$

注意 \(\mathbf{A}^2 = \mathbf{0}\)（零矩阵），所以泰勒展开在第二项就精确截断了：

$$\mathbf{F} = \mathbf{I} + \mathbf{A}\Delta t = \begin{bmatrix} 1 & \Delta t \\ 0 & 1 \end{bmatrix}$$

这恰好就是上一节得到的 \(\mathbf{F}\)！对于这个特殊系统，一阶近似碰巧就是精确解。但并非所有系统都这么幸运。

⚠️ 工程警告：对于快速动态系统（如电机转速控制，带宽 > 100Hz）或 \(\Delta t\) 较大的场景，一阶近似可能导致数值不稳定。症状是协方差 P 发散或状态估计振荡。此时应使用二阶甚至精确的矩阵指数。在 C 语言中，对小矩阵（2×2, 3×3）可以手动展开到二阶或三阶。

三、观测方程——"我能看到什么？"

传感器不一定能直接看到所有状态。GPS 只给位置，不给速度；加速度计只给加速度，不给位置。

观测方程描述了"状态"和"测量值"之间的关系：

$$\mathbf{z}_k = \mathbf{H} \cdot \mathbf{x}_k + \mathbf{v}_k$$

如果 GPS 只测位置，那么：

$$\mathbf{H} = \begin{bmatrix} 1 & 0 \end{bmatrix}, \quad z_k = x_k + v_k$$

其中 \(\mathbf{v}_k\) 是测量噪声，\(\mathbf{H}\) 就像一个"选择器"——从状态向量中挑出传感器能看到的那部分。

四、噪声模型——不确定性的量化

过程噪声 Q

现实中系统不会完美地按照 \(\mathbf{F}\) 运行——有风、有振动、有我们没建模的动态。这些不确定性用过程噪声协方差矩阵 \(\mathbf{Q}\) 来描述：

$$\mathbf{x}_{k+1} = \mathbf{F} \cdot \mathbf{x}_k + \mathbf{B} \cdot u_k + \mathbf{w}_k, \quad \mathbf{w}_k \sim \mathcal{N}(0, \mathbf{Q})$$

对于匀速运动模型（状态 = [位置, 速度]），一个常用的 Q 矩阵是：

$$\mathbf{Q} = q \begin{bmatrix} \frac{\Delta t^3}{3} & \frac{\Delta t^2}{2} \\ \frac{\Delta t^2}{2} & \Delta t \end{bmatrix}$$

其中 \(q\) 是"过程噪声功率谱密度"——说人话就是"你觉得模型有多不靠谱"。\(q\) 越大，滤波器越不信模型，越愿意相信测量。

测量噪声 R

传感器的噪声特性通常写在数据手册里。对 GPS 来说：

$$\mathbf{R} = \sigma_{GPS}^2$$

如果 GPS 精度标称 2.5m CEP（50% 概率圆），换算成标准差大约 \(\sigma \approx 3m\)。

五、二维无人机的完整状态空间

把上面的一维模型扩展到二维，状态向量变成 4 维：

$$\mathbf{x} = \begin{bmatrix} x \\ y \\ v_x \\ v_y \end{bmatrix}$$

因为 x 和 y 方向独立（匀速运动模型下），矩阵是：

$$\mathbf{F} = \begin{bmatrix} 1 & 0 & \Delta t & 0 \\ 0 & 1 & 0 & \Delta t \\ 0 & 0 & 1 & 0 \\ 0 & 0 & 0 & 1 \end{bmatrix}, \quad \mathbf{H} = \begin{bmatrix} 1 & 0 & 0 & 0 \\ 0 & 1 & 0 & 0 \end{bmatrix}$$

可观测性——你的传感器能看到所有状态吗？

这是一个容易被初学者忽略但极其重要的问题：仅凭你的传感器和模型，你能估计出所有状态吗？

判断方法是构造可观测性矩阵（Observability Matrix）：

$$\mathcal{O} = \begin{bmatrix} \mathbf{H} \\ \mathbf{H}\mathbf{F} \\ \mathbf{H}\mathbf{F}^2 \\ \vdots \\ \mathbf{H}\mathbf{F}^{n-1} \end{bmatrix}$$

如果 \(\text{rank}(\mathcal{O}) = n\)（状态维度），则所有状态都是可观测的。

例子：GPS 只测位置，能估计速度吗？

对于二维无人机（状态 = [x, y, vx, vy]），GPS 只测位置：

$$\mathbf{H} = \begin{bmatrix} 1 & 0 & 0 & 0 \\ 0 & 1 & 0 & 0 \end{bmatrix}$$

构造可观测性矩阵（取前两个块就够了，因为 n=4, m=2）：

$$\mathcal{O} = \begin{bmatrix} \mathbf{H} \\ \mathbf{H}\mathbf{F} \end{bmatrix} = \begin{bmatrix} 1 & 0 & 0 & 0 \\ 0 & 1 & 0 & 0 \\ 1 & 0 & \Delta t & 0 \\ 0 & 1 & 0 & \Delta t \end{bmatrix}$$

\(\text{rank}(\mathcal{O}) = 4\) → 所有状态可观测！即使 GPS 不直接测速度，因为 \(\mathbf{F}\) 把位置和速度耦合在一起（位置的变化蕴含了速度信息），滤波器可以从位置的变化率中推断出速度。

但有一个陷阱：弱可观测性

数学上可观测 ≠ 实际上估计得好。如果无人机静止不动，位置几乎不变，速度信息只能从噪声中微弱地体现——速度的协方差收敛极慢。这就是"弱可观测"。

这也解释了为什么 PX4 飞控在初始化时要求你"fly around"（四处飞一飞）——只有在运动中，速度状态才能快速收敛，滤波器才能获得可靠的速度估计。同理，如果你的无人机只做匀速直线飞行，加速度偏差状态就是弱可观测的——需要机动飞行（转弯、加减速）来激发可观测性。

Q 和 R 的确定方法：理论上 R 可以从传感器数据手册得到（但务必在实际安装条件下验证——在工作台上测和装到振动的机架上是两回事）。实际做法：

  1. 让无人机静止放置，采集 GPS 数据 5~10 分钟，计算方差 → 这就是你的 R
  2. Q 没法直接测量，通常从"你对模型有多大信心"出发拍一个初值，然后用 NIS（归一化新息平方）来在线调整
/* 实用代码：在线计算传感器方差（Welford 算法，单遍扫描）*/
typedef struct {
    uint32_t n;
    float mean;
    float m2;   /* 累积平方差 */
} Variance_t;

static inline void var_update(Variance_t *v, float x) {
    v->n++;
    float delta = x - v->mean;
    v->mean += delta / v->n;
    v->m2  += delta * (x - v->mean);
}

static inline float var_get(const Variance_t *v) {
    return (v->n > 1) ? v->m2 / (v->n - 1) : 0.0f;
}

状态向量维度的选择：每多加一维状态，协方差矩阵 P 就多一行一列。P 是 n×n 对称矩阵，存储量为 n(n+1)/2 个 float。4 维状态只需 10 个 float（40 字节），但 9 维就需要 45 个 float（180 字节）。在 Cortex-M0 上，这点内存可能就是关键瓶颈。

Allan 方差——IMU 噪声标定的标准工具：传感器数据手册上标注的噪声密度（Noise Density）就是 Allan 方差曲线在 \(\tau=1\) s 处的值。对于 MEMS 陀螺仪，关键参数是角度随机游走（ARW, Angular Random Walk），典型值为 0.1~1 °/√hr——这直接决定了你的过程噪声 \(\mathbf{Q}\) 中陀螺相关分量的大小。

实用标定方法：将 IMU 静置在稳定平面上，采集 1 小时以上的数据，然后用 Allan 方差分析工具（MATLAB 的 allanvar 或 Python 的 allantools）自动提取噪声参数。这比从数据手册抄参数可靠得多，因为实际安装环境（振动、温度）会显著改变噪声特性。

第三章：一场数据的融合

预测与更新的直觉——两个高斯分布如何"合体"

本章目标

  • 直观理解"预测分布"和"测量分布"的融合过程
  • 掌握卡尔曼增益 K 的物理含义
  • 为下一章的五个公式做好直觉铺垫

一、一个最简单的融合问题

先忘掉矩阵，回到最简单的情况：你有两个关于同一个量（比如温度、位置）的估计：

  • 预测：基于你的物理模型，你认为温度是 22°C，但你对这个估计不太确定（标准差 3°C）
  • 测量：温度计读数是 25°C，精度还不错（标准差 1°C）

最终你应该更相信温度计（因为它更准），结果应该接近 25°C。但具体是多少？卡尔曼滤波给出了数学上最优的答案。

贝叶斯视角——卡尔曼滤波的"真正身份"

MIT 的课程（6.011, 16.322）在推导卡尔曼滤波时，不是从工程直觉出发，而是从贝叶斯定理开始：

$$p(x|z) \propto p(z|x) \cdot p(x)$$

翻译成人话：

  • 先验 \(p(x)\)：在看到测量之前，你对状态的信念（= 预测分布）
  • 似然 \(p(z|x)\)：如果状态是 \(x\)，观测到 \(z\) 的概率（= 测量模型）
  • 后验 \(p(x|z)\)：看到测量之后，你对状态的更新信念（= 融合结果）

当先验和似然都是高斯分布时：

$$p(x) = \mathcal{N}(x;\, \hat{x}_{k|k-1},\, P_{k|k-1}), \quad p(z|x) = \mathcal{N}(z;\, Hx,\, R)$$

后验也是高斯分布（高斯的共轭性），而且后验的均值和方差恰好就是卡尔曼滤波更新公式！完整的贝叶斯后验写出来是：

$$p(x|z) \propto \mathcal{N}(z;\, Hx,\, R) \cdot \mathcal{N}(x;\, \hat{x}_{k|k-1},\, P_{k|k-1})$$

这揭示了卡尔曼滤波的真正身份：它不是一个工程经验公式，而是线性高斯系统下贝叶斯推断的精确解。

关键推论：当系统是非线性的（如飞行器姿态动力学），或者噪声不是高斯的（如重尾噪声、多模态分布），卡尔曼滤波不再是最优的。这就是为什么存在 EKF（对非线性的妥协）、UKF（更好的非线性近似）和粒子滤波（完全抛弃高斯假设）。

二、高斯分布的乘积——融合的数学

如果预测和测量都服从高斯分布：

$$\text{预测: } \mathcal{N}(\mu_p, \sigma_p^2), \quad \text{测量: } \mathcal{N}(\mu_z, \sigma_z^2)$$

那么融合后的后验分布也是高斯的（这是卡尔曼滤波只适用于线性高斯系统的根本原因），其参数为：

$$\mu_{后验} = \mu_p + K \cdot (\mu_z - \mu_p)$$ $$\sigma_{后验}^2 = (1 - K) \cdot \sigma_p^2$$

其中卡尔曼增益：

$$K = \frac{\sigma_p^2}{\sigma_p^2 + \sigma_z^2}$$

直觉解读：

  • 当测量很准（\(\sigma_z \to 0\)）→ \(K \to 1\) → 完全相信测量
  • 当测量很差（\(\sigma_z \to \infty\)）→ \(K \to 0\) → 完全相信预测
  • 融合后的不确定度 \(\sigma_{后验}\) 永远比两个输入都小——信息只会增加！

信息永远增加——传感器融合的基本定理

"融合后的不确定度永远不会大于任何一个输入的不确定度"——这不是巧合，而是数学定理。

用信息量（精度，\(1/\sigma^2\)）来理解更自然：

$$\frac{1}{\sigma_{后验}^2} = \frac{1}{\sigma_p^2} + \frac{1}{\sigma_z^2}$$

信息是相加的！即使一个传感器很差（信息量很小），它也在贡献正信息，融合后的总信息量一定更大。这就是 MIT 所说的"信息永不减少"原则（Information Never Decreases）。

这个视角也解释了为什么多传感器融合永远值得——哪怕加一个很差的传感器，它也只会让估计更好（最坏情况是几乎没帮助），绝不会让估计变差。

"呼吸的节奏"——预测-更新的宏观行为

如果你运行上面的交互实验足够多步，会发现一个有趣的现象：协方差 P 的"一胀一缩"逐渐趋于一个稳定的振幅。预测后 P 增大一点，更新后 P 缩回来一点，但两者之间的跳动幅度越来越小，最终几乎不变。

这不是巧合。对于线性时不变系统（F, H, Q, R 都是常数），协方差 P 最终会收敛到代数 Riccati 方程（Algebraic Riccati Equation, ARE）的解：

$$\mathbf{P}_\infty = \mathbf{F}\mathbf{P}_\infty\mathbf{F}^T + \mathbf{Q} - \mathbf{F}\mathbf{P}_\infty\mathbf{H}^T(\mathbf{H}\mathbf{P}_\infty\mathbf{H}^T + \mathbf{R})^{-1}\mathbf{H}\mathbf{P}_\infty\mathbf{F}^T$$

对应的卡尔曼增益也收敛到一个常数 \(\mathbf{K}_\infty\)。这意味着：

工程捷径：在很多嵌入式系统中，可以离线预计算稳态增益 \(\mathbf{K}_\infty\)，然后在运行时直接用这个常数——省掉所有的协方差传播和矩阵求逆！

更新公式退化为：\(\hat{x}_{k} = \mathbf{F}\hat{x}_{k-1} + \mathbf{K}_\infty(z_k - \mathbf{H}\mathbf{F}\hat{x}_{k-1})\)

计算量从矩阵运算降到简单的乘加——在 Cortex-M0 上也能轻松跑。

事实上，经典的互补滤波器（Complementary Filter）本质上就是一个特定 Q/R 比值下的稳态卡尔曼滤波器。所以如果有人告诉你"互补滤波 vs 卡尔曼滤波"是两种不同的方法——其实互补滤波是卡尔曼滤波的一个特例。

四、预测-更新循环的可视化

在真正的卡尔曼滤波中，这个融合过程反复进行：

  1. 预测步：用物理模型推算下一时刻的状态 → 不确定度增大（协方差变大）
  2. 更新步：拿到新的测量值 → 融合 → 不确定度减小（协方差变小）

就像呼吸一样，一胀一缩，不确定度在每一步收敛到一个稳定范围。

嵌入式开发者笔记

K 的计算是瓶颈：在一维情况下 K 只是一个除法。但在多维系统中，卡尔曼增益的计算涉及矩阵求逆：

$$\mathbf{K} = \mathbf{P}\mathbf{H}^T(\mathbf{H}\mathbf{P}\mathbf{H}^T + \mathbf{R})^{-1}$$

对于 n 维状态、m 维观测，需要对 m×m 矩阵求逆。当 m=2（GPS 输出 x,y）时只需求 2×2 逆矩阵（用公式法就行）；但如果你融合了多个传感器（比如 GPS + 气压计 + 磁力计），m 可能达到 6 或更多，这时候可能需要 Cholesky 分解。

/* 2x2 矩阵求逆 —— 大部分飞控的 GPS 融合够用了 */
static void mat2_inv(const float A[2][2], float Ainv[2][2]) {
    float det = A[0][0]*A[1][1] - A[0][1]*A[1][0];
    float inv_det = 1.0f / det;  /* 实际使用前检查 det != 0 */
    Ainv[0][0] =  A[1][1] * inv_det;
    Ainv[0][1] = -A[0][1] * inv_det;
    Ainv[1][0] = -A[1][0] * inv_det;
    Ainv[1][1] =  A[0][0] * inv_det;
}

定点数实现：如果你的 MCU 没有 FPU（比如 Cortex-M0），可以用 Q16.16 定点数表示 K。K 的范围总是 [0, 1]，非常适合定点表示。但要注意协方差矩阵的数值范围可能很大（位置单位是米的平方），需要仔细选择定点格式。

信息滤波器（Information Filter）：卡尔曼滤波有一个等价形式——用信息矩阵 \(\mathbf{P}^{-1}\) 代替协方差矩阵 \(\mathbf{P}\)。在这种形式下，多传感器融合变得极其简单：只需把各传感器的信息矩阵和信息向量相加即可。不需要复杂的串行融合顺序，也不需要处理跨传感器的相关性。

分布式传感器网络：在配备多个 GPS 接收机或多个 IMU 的系统中（如 PX4 支持 3 IMU 冗余），信息滤波器是首选，因为融合 = 简单的矩阵加法。PX4 的多 IMU 处理就使用了一种信息融合的变体——每个 IMU 独立产生信息贡献，最终汇总。这种架构天然支持传感器的热插拔和故障隔离。

一、五个方程——就这么简单

卡尔曼滤波分两步：预测（Predict）和更新（Update）。一共五个方程，两个用于预测，三个用于更新。

预测步（Predict）

方程 ①：状态预测
$$\hat{\mathbf{x}}_{k|k-1} = \mathbf{F} \hat{\mathbf{x}}_{k-1|k-1} + \mathbf{B} \mathbf{u}_k$$

用物理模型推算下一时刻的状态。F 是状态转移矩阵，B·u 是控制输入（如 IMU 加速度）。

方程 ②：协方差预测
$$\mathbf{P}_{k|k-1} = \mathbf{F} \mathbf{P}_{k-1|k-1} \mathbf{F}^T + \mathbf{Q}$$

不确定度（协方差矩阵）在预测后变大，增大量由过程噪声 Q 决定。
维度：n×n（n 是状态维数）。

更新步（Update）

方程 ③：卡尔曼增益
$$\mathbf{K}_k = \mathbf{P}_{k|k-1} \mathbf{H}^T (\mathbf{H} \mathbf{P}_{k|k-1} \mathbf{H}^T + \mathbf{R})^{-1}$$

K 决定了"相信测量多少"。括号里的逆矩阵维度是 m×m（m 是观测维数），通常远小于 n。

方程 ④：状态更新
$$\hat{\mathbf{x}}_{k|k} = \hat{\mathbf{x}}_{k|k-1} + \mathbf{K}_k (\mathbf{z}_k - \mathbf{H} \hat{\mathbf{x}}_{k|k-1})$$

\(\mathbf{z}_k - \mathbf{H}\hat{\mathbf{x}}_{k|k-1}\) 叫新息（Innovation），就是"测量和预测之间的差距"。K 越大，校正越多。

方程 ⑤：协方差更新
$$\mathbf{P}_{k|k} = (\mathbf{I} - \mathbf{K}_k \mathbf{H}) \mathbf{P}_{k|k-1}$$

更新后不确定度缩小。注意这个简化形式在数值上可能不稳定（见第七章 Joseph 形式）。

二·五、稳态卡尔曼增益——嵌入式工程师的捷径

你可能注意到了一个规律：随着预测-更新循环不断进行，协方差矩阵 P 和卡尔曼增益 K 最终会收敛到固定值。这不是巧合——这是数学上可以证明的。

当 \(\mathbf{F}\)、\(\mathbf{H}\)、\(\mathbf{Q}\)、\(\mathbf{R}\) 都是常数矩阵（时不变系统），P 会收敛到一个稳态值 \(\mathbf{P}_\infty\)，它满足代数 Riccati 方程（ARE）：

$$\mathbf{P}_\infty = \mathbf{F}\left[\mathbf{P}_\infty - \mathbf{P}_\infty \mathbf{H}^T(\mathbf{H}\mathbf{P}_\infty \mathbf{H}^T + \mathbf{R})^{-1}\mathbf{H}\mathbf{P}_\infty\right]\mathbf{F}^T + \mathbf{Q}$$

对应的稳态卡尔曼增益就是一个常数矩阵：

$$\mathbf{K}_\infty = \mathbf{P}_\infty \mathbf{H}^T(\mathbf{H}\mathbf{P}_\infty \mathbf{H}^T + \mathbf{R})^{-1}$$

这意味着什么？你根本不需要在运行时更新 P 或计算 K！工程流程是这样的：

  1. 在 MATLAB/Python 里跑完整的卡尔曼滤波，迭代几十步直到 K 收敛
  2. 把收敛后的 \(\mathbf{K}_\infty\) 提取出来，硬编码到固件里
  3. 运行时只做 \(\hat{\mathbf{x}} = \mathbf{F}\hat{\mathbf{x}} + \mathbf{B}\mathbf{u} + \mathbf{K}_\infty(\mathbf{z} - \mathbf{H}\mathbf{F}\hat{\mathbf{x}})\)——一个矩阵-向量乘法搞定

计算量从 O(n³) 暴降到 O(n²)——因为省掉了协方差矩阵的乘法和求逆。对于资源极度受限的 8 位 MCU（比如 ATmega328），这可能是唯一可行的方案。

你可能已经用过稳态 KF 而不自知：互补滤波器（Complementary Filter）本质上就是一个稳态卡尔曼滤波器！比如经典的 IMU 姿态估计 angle = 0.98*(angle+gyro*dt) + 0.02*accel_angle，那个 0.98 和 0.02 就对应于 \(\mathbf{I}-\mathbf{K}_\infty\mathbf{H}\) 和 \(\mathbf{K}_\infty\) 的元素。Madgwick、Mahony 滤波器也是这个思路。

使用条件：系统必须是可检测（detectable）且可镇定（stabilizable）的，这基本等价于"所有不稳定的状态都能被观测到"。对于典型的位置-速度-加速度模型，这个条件几乎总是满足的。

什么时候不能用稳态增益？

  • GPS 信号质量变化（室内/室外切换、城市峡谷多径效应）→ R 不是常数
  • 机动目标跟踪（加速/转弯时 Q 应该增大）→ Q 不是常数
  • 传感器在线切换（某个传感器掉线/恢复）→ H 矩阵变化
  • 滤波器刚启动的瞬态阶段（P 还没收敛，用稳态 K 会错过快速收敛的机会）

/* kf2d.h — 2D 位置-速度卡尔曼滤波器
 * 状态: [x, y, vx, vy]  (n=4)
 * 观测: [x, y]           (m=2)
 */
#define KF_N 4   /* 状态维数 */
#define KF_M 2   /* 观测维数 */

typedef struct {
    float x[KF_N];           /* 状态向量 */
    float P[KF_N][KF_N];     /* 协方差矩阵 */
    float F[KF_N][KF_N];     /* 状态转移 */
    float H[KF_M][KF_N];     /* 观测矩阵 */
    float Q[KF_N][KF_N];     /* 过程噪声 */
    float R[KF_M][KF_M];     /* 测量噪声 */
    float K[KF_N][KF_M];     /* 卡尔曼增益 */
    float dt;                /* 时间步长 */
} KF2D_t;

void kf2d_init(KF2D_t *kf, float dt);
void kf2d_predict(KF2D_t *kf, float ax, float ay);

void kf2d_predict(KF2D_t *kf, float ax, float ay) {
    float *x = kf->x;
    float dt = kf->dt;

    /* ① 状态预测: x = F*x + B*u */
    float x0 = x[0] + x[2]*dt + 0.5f*ax*dt*dt;
    float x1 = x[1] + x[3]*dt + 0.5f*ay*dt*dt;
    float x2 = x[2] + ax*dt;
    float x3 = x[3] + ay*dt;
    x[0]=x0; x[1]=x1; x[2]=x2; x[3]=x3;

    /* ② 协方差预测: P = F*P*F' + Q */
    /* 这里手动展开，避免通用矩阵乘法的开销 */
    float P[4][4];
    /* ... (展开的矩阵运算，见完整实现) ... */
    /* 简化：对角元素加上 Q */
    for(int i = 0; i < KF_N; i++)
        for(int j = 0; j < KF_N; j++)
            kf->P[i][j] += kf->Q[i][j]; /* 近似 */
}

void kf2d_update(KF2D_t *kf, float zx, float zy) {
    /* ③ 卡尔曼增益 K = P*H'*(H*P*H'+R)^-1 */
    /* 因为 H=[I 0], 所以 H*P*H'=P的左上2x2块 */
    float S[2][2]; /* 新息协方差 */
    S[0][0] = kf->P[0][0] + kf->R[0][0];
    S[0][1] = kf->P[0][1] + kf->R[0][1];
    S[1][0] = kf->P[1][0] + kf->R[1][0];
    S[1][1] = kf->P[1][1] + kf->R[1][1];

    float det = S[0][0]*S[1][1] - S[0][1]*S[1][0];
    float inv_det = 1.0f / det;
    float Si[2][2] = {
        { S[1][1]*inv_det, -S[0][1]*inv_det},
        {-S[1][0]*inv_det,  S[0][0]*inv_det}
    };

    /* K = P * H' * Si (H'就是前两列的单位矩阵) */
    for(int i = 0; i < KF_N; i++)
        for(int j = 0; j < KF_M; j++) {
            kf->K[i][j] = 0;
            for(int k = 0; k < KF_M; k++)
                kf->K[i][j] += kf->P[i][k] * Si[k][j];
        }

    /* ④ 状态更新: x = x + K*(z - H*x) */
    float innov[2] = { zx - kf->x[0], zy - kf->x[1] };
    for(int i = 0; i < KF_N; i++)
        kf->x[i] += kf->K[i][0]*innov[0] + kf->K[i][1]*innov[1];

    /* ⑤ 协方差更新: P = (I - K*H)*P */
    float P_new[KF_N][KF_N];
    for(int i = 0; i < KF_N; i++)
        for(int j = 0; j < KF_N; j++) {
            P_new[i][j] = kf->P[i][j];
            for(int k = 0; k < KF_M; k++)
                P_new[i][j] -= kf->K[i][k] * kf->P[k][j];
        }
    for(int i = 0; i < KF_N; i++)
        for(int j = 0; j < KF_N; j++)
            kf->P[i][j] = P_new[i][j];
}

四·五、你的滤波器健康吗？——新息序列的秘密

调 Q 和 R 是卡尔曼滤波最让人头疼的事。很多人靠"手感"和"经验"，但其实有一个系统化的诊断方法——检查新息序列（Innovation Sequence）。

回忆方程 ④ 中的新息 \(\boldsymbol{\nu}_k = \mathbf{z}_k - \mathbf{H}\hat{\mathbf{x}}_{k|k-1}\)。如果你的滤波器调得完美，新息序列会有三个"神奇"的性质（MIT 16.322 课程称之为 innovation sequence properties）：

新息序列三性质（滤波器健康指标）

性质 1：零均值

$$E[\boldsymbol{\nu}_k] = \mathbf{0}$$

如果新息持续偏正或偏负 → 你的模型有系统性偏差（比如忘了建模风力、IMU 偏差没补偿）。

性质 2：白噪声（无自相关）

$$E[\boldsymbol{\nu}_k \boldsymbol{\nu}_j^T] = \mathbf{0}, \quad k \neq j$$

如果相邻新息之间有相关性（像"有规律地上下波动"）→ Q 太小了，滤波器过度相信模型，来不及跟上真实状态的变化。

性质 3：协方差 = S

$$E[\boldsymbol{\nu}_k \boldsymbol{\nu}_k^T] = \mathbf{S}_k = \mathbf{H}\mathbf{P}_{k|k-1}\mathbf{H}^T + \mathbf{R}$$

如果新息的实际方差远大于 S 预测的方差 → R 太小了，你低估了测量噪声。反之 → R 太大了。

实操方法：把新息序列存下来（飞行日志），画出来看。用归一化新息平方（Normalized Innovation Squared，NIS）来定量检查：

$$\text{NIS}_k = \boldsymbol{\nu}_k^T \mathbf{S}_k^{-1} \boldsymbol{\nu}_k$$

如果滤波器正确调谐，NIS 应该服从 \(\chi^2(m)\) 分布（m 是观测维数）。对于 m=2，NIS 的均值应该约等于 2。如果均值远大于 2，说明 R 设小了或 Q 设小了；如果远小于 2，说明你的噪声参数设得太保守了（滤波器在"浪费"测量信息）。

这是调参的金标准：不要瞎猜 Q 和 R，而是迭代调整直到新息序列满足上述三个性质。

四·六、计算复杂度分析

卡尔曼滤波到底有多"贵"？这决定了你能在什么硬件上跑多大维度的滤波器。

运算步骤 主要计算 复杂度
① 状态预测 F·x矩阵×向量O(n²)
② 协方差预测 F·P·FT+Q矩阵×矩阵×矩阵O(n³)
③ 卡尔曼增益 P·HT·S-1矩阵乘 + m×m 求逆O(n²m + m³)
④ 状态更新 x + K·ν矩阵×向量O(nm)
⑤ 协方差更新 (I-KH)·P矩阵×矩阵O(n²m)
总计（每步）O(n³)（n>m 时）

来看看实际的数字：

  • n=4, m=2（本章的 2D 位置-速度）：约 200 次乘法 + 150 次加法 → Cortex-M4F@168MHz 上约 5μs，轻轻松松
  • n=15, m=6（完整 INS：四元数+速度+位置+偏差）：约 8000 次乘法 → 约 100μs，400Hz 没问题
  • n=2003, m=2（EKF-SLAM，1000 个路标）：P 矩阵是 2003×2003，光存储就要 16MB，每步约 400 万次乘法 → 在 MCU 上完全不可行，这就是为什么 SLAM 要用粒子滤波或图优化

优化技巧：利用 P 的对称性，F·P·FT 的实际运算量可以减半；如果 F 是稀疏的（很多零元素），手动展开比通用矩阵乘法快 3-5 倍——这就是为什么飞控代码里的 KF 都是手写展开而不是调用 BLAS 库。

协方差矩阵的对称存储：P 是对称矩阵（P[i][j] == P[j][i]），实际上只需存储上三角部分。4×4 矩阵从 16 个 float 减到 10 个。这在内存紧张的 MCU 上很实用：

/* 上三角存储: P[0][0], P[0][1], P[0][2], P[0][3],
 *                      P[1][1], P[1][2], P[1][3],
 *                               P[2][2], P[2][3],
 *                                        P[3][3]
 * 索引映射: idx = i*n - i*(i-1)/2 + (j-i)
 */
#define P_IDX(i,j,n) ((i)*(n) - (i)*((i)-1)/2 + ((j)-(i)))

float P_upper[10]; /* 4*(4+1)/2 = 10 */

static inline float P_get(int i, int j) {
    return (i <= j) ? P_upper[P_IDX(i,j,4)]
                    : P_upper[P_IDX(j,i,4)];
}

数值稳定性：方程 ⑤ 的简化形式 \(P = (I-KH)P\) 可能因为浮点误差导致 P 不对称甚至负定。Joseph 形式更安全：

$$\mathbf{P} = (\mathbf{I}-\mathbf{K}\mathbf{H})\mathbf{P}(\mathbf{I}-\mathbf{K}\mathbf{H})^T + \mathbf{K}\mathbf{R}\mathbf{K}^T$$

计算量多了约 50%，但能保证 P 的对称正定性。在长时间运行的飞控中，这点开销很值得。

稳态增益的实际应用：在 PX4 的高度估计器（altitude estimator）中，气压计融合的卡尔曼增益本质上是预计算好的几个常数。很多真实系统还会用增益调度（scheduled gains）——为不同飞行阶段（悬停 vs 巡航 vs 高过载机动）预计算不同的 K 值，根据当前状态切换。

那为什么 PX4 的主 EKF（ECL-EKF）还是用完整的协方差更新而不是稳态增益？因为 GPS 信号质量是时变的——从开阔地飞到建筑物旁边，多径效应让 R 突然增大好几倍。室内飞行甚至完全丢失 GPS，此时 H 矩阵直接降维。稳态增益处理不了这种动态变化。

在看完上面那一大段 KF 代码后，你可能会想：有没有更简单的方案？当然有——互补滤波器（Complementary Filter），它本质上就是第四章讲的稳态卡尔曼滤波器的特殊形式。

对于位置估计，一个互补滤波器可以写成一行：

$$\hat{x}_k = \alpha \cdot x_{GPS} + (1-\alpha) \cdot (\hat{x}_{k-1} + v \cdot \Delta t)$$

float comp_filter(float gps_pos, float accel, float dt) {
    static float pos = 0, vel = 0;
    vel += accel * dt;
    pos = 0.98f * (pos + vel * dt) + 0.02f * gps_pos;
    return pos;
}

三·五、马氏距离门限——别让坏数据毁了你的滤波器

在真实飞行中，GPS 偶尔会给出严重错误的读数——比如在城市峡谷中信号反射（multipath），位置突然跳几十米。如果你把这种"毒数据"直接喂给卡尔曼滤波器，它会被猛烈拉偏，可能需要好几秒才能恢复。

解决方法：在做 KF 更新之前，先检查新息是否"合理"。用马氏距离（Mahalanobis Distance）来判断：

$$d^2 = \boldsymbol{\nu}^T \mathbf{S}^{-1} \boldsymbol{\nu}$$

其中 \(\boldsymbol{\nu}\) 是新息，\(\mathbf{S} = \mathbf{H}\mathbf{P}\mathbf{H}^T + \mathbf{R}\) 是新息的期望协方差。如果滤波器正确调谐，\(d^2\) 服从 \(\chi^2(m)\) 分布。

设定一个门限：如果 \(d^2\) 超过 \(\chi^2\) 分布的 99% 分位数，就拒绝这次测量——它几乎肯定是异常值。

/* 马氏距离门限检测——在 KF update 前调用 */
/* 对于 m=2 的 GPS 测量 */

         + 2*innov[0]*Si[0][1]*innov[1];

    log_warning("GPS innovation gate reject: d2=%.1f", d2);
    return;  /* 跳过更新，继续预测 */
}

/* 通过门限检测，正常执行 KF update */
kf2d_update(&kf, gps_x, gps_y);

关键原则：拒绝异常值后，不要重置滤波器——直接跳过更新步，让预测继续运行。滤波器会用惯性推算撑过没有 GPS 的时段，等下一次正常的 GPS 数据到来再校正。PX4 和 ArduPilot 的 EKF 都实现了这种新息门限检测（innovation gate test），对每个传感器的每次更新都会做。

异步更新——飞控中的关键设计

  • 使用 Joseph 形式更新 P，Mahalanobis 门限剔除异常值
  • 源码：github.com/PX4/PX4-ECL

一、为什么需要 EKF？

在第五章中，我们假设 GPS 直接给出了 \((x, y)\) 坐标——这是一个线性的观测关系。但在很多实际场景中，传感器的输出和状态之间是非线性的：

  • 雷达测距测角：测量的是距离 \(r = \sqrt{x^2 + y^2}\) 和角度 \(\theta = \arctan(y/x)\)，而不是 x, y
  • GPS 伪距：实际测量的是到每颗卫星的距离，需要经过非线性方程解算
  • 磁力计：磁场方向和机体姿态之间是三角函数关系

这时候观测方程变成：

$$\mathbf{z}_k = h(\mathbf{x}_k) + \mathbf{v}_k$$

注意这里的 \(h(\cdot)\) 是一个非线性函数，不再是简单的矩阵乘法 \(\mathbf{H}\mathbf{x}\)。标准卡尔曼滤波的公式直接用不了了。

二、EKF 的核心思想：在当前点展开

EKF 的处理方式简单粗暴但有效：在当前估计点对非线性函数做一阶泰勒展开（线性化），然后用标准卡尔曼滤波的公式。

具体来说，对于观测函数 \(h(\mathbf{x})\)，在当前预测值 \(\hat{\mathbf{x}}_{k|k-1}\) 处求雅可比矩阵：

$$\mathbf{H}_k = \frac{\partial h}{\partial \mathbf{x}} \bigg|_{\mathbf{x}=\hat{\mathbf{x}}_{k|k-1}}$$

然后用这个局部线性化的 \(\mathbf{H}_k\) 代替常数矩阵 H，其余步骤和标准 KF 一样——就这么简单。

雷达测距测角的例子

状态 \(\mathbf{x} = [x, y, v_x, v_y]^T\)，观测 \(\mathbf{z} = [r, \theta]^T\)：

$$h(\mathbf{x}) = \begin{bmatrix} \sqrt{x^2 + y^2} \\ \arctan(y / x) \end{bmatrix}$$

雅可比矩阵：

$$\mathbf{H}_k = \begin{bmatrix} \frac{x}{\sqrt{x^2+y^2}} & \frac{y}{\sqrt{x^2+y^2}} & 0 & 0 \\ \frac{-y}{x^2+y^2} & \frac{x}{x^2+y^2} & 0 & 0 \end{bmatrix}$$

EKF 的改动很小：

  1. 预测步：不变（如果状态方程是线性的）
  2. 更新步：把 \(\mathbf{H}\) 替换为 \(\mathbf{H}_k\)（在当前估计点算的雅可比），把 \(\mathbf{H}\mathbf{x}\) 替换为 \(h(\mathbf{x})\)
  3. 新息变成 \(\mathbf{z}_k - h(\hat{\mathbf{x}}_{k|k-1})\) 而不是 \(\mathbf{z}_k - \mathbf{H}\hat{\mathbf{x}}_{k|k-1}\)

二·五、误差状态卡尔曼滤波（ESKF）——真实飞控的选择

标准 EKF 直接估计完整的状态 \(\mathbf{x}\)（位置、速度、姿态...），然后在当前估计点做线性化。但在真实的惯性导航系统（INS）中，几乎所有专业实现都用一个更聪明的变体：误差状态卡尔曼滤波（Error-State Kalman Filter，ESKF）。

核心思想是把状态分成两部分：

$$\mathbf{x}_{true} = \mathbf{x}_{nom} \oplus \delta\mathbf{x}$$
  • \(\mathbf{x}_{nom}\)：名义状态（nominal state）——用完整的非线性方程传播，不做任何线性化
  • \(\delta\mathbf{x}\)：误差状态（error state）——用 EKF 估计，始终保持很小
  • \(\oplus\)：对于位置/速度就是普通加法；对于旋转是四元数乘法

为什么这样做更好？

  1. 线性化总是精确的：因为 \(\delta\mathbf{x}\) 始终很小（每次更新后都被"注入"名义状态并重置为零），所以一阶泰勒展开的误差极小。标准 EKF 在大角度旋转时线性化误差可能很大，ESKF 则不会。
  2. 避免旋转表示的奇异性：名义状态用四元数（4 个参数）表示旋转，但误差状态只需要 3 个参数（旋转误差向量）。这样 P 矩阵小 1 维，而且不会遇到万向锁问题。
  3. 名义传播是"免费"的精度：非线性传播不引入线性化误差，等于白拿了一段精确的积分，只在校正时才用近似。
  4. 工业标准：PX4、ArduPilot、Google Cartographer、VINS-Mono、MSCKF 全都用 ESKF。

代码结构对比：

/* ===== 标准 EKF ===== */
x = f(x, u);           /* 非线性传播（精确） */
F = df/dx|_{x};         /* 在 x 处求雅可比（x 可能很大，线性化误差大） */
P = F * P * F' + Q;

/* 更新 */
H = dh/dx|_{x};
K = P * H' * inv(H*P*H' + R);
x = x + K * (z - h(x));
P = (I - K*H) * P;

/* ===== 误差状态 KF (ESKF) ===== */
x_nom = f(x_nom, u);    /* 非线性传播（精确，不做线性化！） */
F_err = df_err/d(δx);   /* 误差状态雅可比（δx ≈ 0，线性化超精确） */
P = F_err * P * F_err' + Q;

/* 更新 */
H_err = dh/d(δx);
K = P * H_err' * inv(H_err*P*H_err' + R);
δx = K * (z - h(x_nom));        /* 估计误差 */
x_nom = x_nom ⊕ δx;             /* 注入校正 */
δx = 0;                          /* 重置误差状态 */
P = (I - K*H_err) * P;           /* 可选：同时做 P 的重置变换 */

注意最关键的区别：名义状态的传播 x_nom = f(x_nom, u) 和标准 EKF 一样是用精确的非线性方程，但误差状态的雅可比 \(\mathbf{F}_{err}\) 是在 \(\delta\mathbf{x} \approx 0\) 处计算的——这意味着线性化点永远在"正确"的位置附近，不会随着状态漂移而恶化。

三·五、可观测性分析——不是所有状态都看得见

在线性 KF 中，可观测性是由 \((\mathbf{F}, \mathbf{H})\) 决定的固定属性——要么可观测，要么不可观测。但在 EKF 中，情况更加微妙：可观测性取决于轨迹。

这听起来很抽象，看几个飞控中的真实例子就懂了：

  • 直线飞行 + 仅 GPS 位置：航向角（yaw）不可观测。因为 GPS 只给位置不给朝向，而沿直线飞行时，你无法区分"机头朝前飞"和"机头歪着侧飞"——位置轨迹是一样的。
  • 悬停 + GPS 位置：速度是弱可观测的。位置测量可以慢慢推断出"速度为零"，但收敛很慢，因为静止时位置变化量几乎为零。
  • 匀速直线飞行：加速度偏差不可观测。因为偏差产生的效果和一个恒定的速度增量无法区分——需要变速或变向飞行才能让偏差"露出马脚"。

实用判断法则：如果一个状态不可观测或弱可观测，它对应的 P 矩阵对角元素不会收敛——会持续增长或停留在很大的值。如果你在飞行日志中看到某个 P 对角元素一直不收敛，先别急着调 Q，很可能是可观测性的问题。

这就是为什么飞控需要这么多传感器的协同配合：

  • 磁力计：提供航向角的可观测性（在低速和悬停时尤其关键）
  • GPS 速度（不仅是位置）：提供航向角在中高速飞行时的可观测性，同时加速速度状态的收敛
  • 初始化时的运动要求：PX4 要求解锁后先做一些运动（或等待一段时间），就是为了积累足够的可观测性来收敛偏差状态
  • 光流传感器：在无 GPS 环境中提供速度的可观测性，但需要已知高度（又一个可观测性约束）

/* EKF 雷达观测更新 —— 关键差异标注 */
void ekf_radar_update(KF2D_t *kf, float r_meas, float theta_meas) {
    float x = kf->x[0], y = kf->x[1];
    float r_pred = sqrtf(x*x + y*y);
    float theta_pred = atan2f(y, x);

    /* 防止 r_pred 为零导致除零 */
    if (r_pred < 1e-6f) r_pred = 1e-6f;

    /* EKF 关键：在当前估计点计算雅可比 */
    float H[2][4] = {
        { x/r_pred,        y/r_pred,       0, 0 },
        { -y/(r_pred*r_pred), x/(r_pred*r_pred), 0, 0 }
    };

    /* 新息 = 实测 - h(x_pred)，注意角度要归一化 */
    float innov[2] = {
        r_meas - r_pred,
        angle_wrap(theta_meas - theta_pred)  /* 关键！ */
    };

    /* 后续步骤和标准 KF 完全一样：算 S, K, 更新 x 和 P */
    /* ... */
}

/* 角度归一化到 [-π, π] —— EKF 处理角度时必须做 */
static inline float angle_wrap(float a) {
    while (a >  M_PI) a -= 2*M_PI;
    while (a < -M_PI) a += 2*M_PI;
    return a;
}

嵌入式开发者笔记

雅可比矩阵的计算策略

  • 解析法：手动推导，效率最高，适合固定的观测模型。大部分飞控项目用这种。
  • 数值法：用 \(\frac{\partial h}{\partial x_i} \approx \frac{h(x+\delta e_i) - h(x-\delta e_i)}{2\delta}\)，实现简单但计算量翻倍。调试阶段好用。
  • 自动微分：在 PC 端用 AD 工具生成 C 代码，然后移植到嵌入式。适合复杂模型。

EKF 的常见坑

  • 角度跳变：当 θ 从 π 跳到 -π 时，新息会爆表。必须做角度归一化。
  • 线性化误差：如果系统高度非线性（比如目标在雷达正上方），EKF 可能发散。这时考虑 UKF。
  • atan2 vs atan：永远用 atan2(y,x)，不要用 atan(y/x)。后者分不清象限，而且 x=0 时除零。

计算量对比：EKF 相比 KF 多了雅可比矩阵计算（对 4 维状态 2 维观测，多了约 8 次乘法加几次三角函数）。在 Cortex-M4F 上，一次 sqrtf + atan2f 大约 30~50 个时钟周期，微不足道。

迭代 EKF（IEKF）：标准 EKF 在更新步只线性化一次，但如果观测方程高度非线性，一次线性化可能不够准。IEKF 的做法是在更新步重复线性化 2-3 次：每次用更新后的 \(\hat{\mathbf{x}}\) 重新计算雅可比 \(\mathbf{H}_k\) 和新息，然后再做一次更新。

  • 对于高度非线性的观测方程（如 SLAM 中的相机投影模型、近距离雷达跟踪），IEKF 可以显著提高精度
  • 代价：计算量翻 2-3 倍，但在 Cortex-M7@400MHz 上通常可以接受
  • 收敛判据：当相邻两次迭代的状态变化量 \(\|\delta\mathbf{x}\|\) 小于阈值时停止

更高级的替代方案：UKF（Unscented Kalman Filter）不需要手算雅可比，用 sigma 点采样来逼近非线性变换。代价是对 n 维状态需要传播 2n+1 个 sigma 点，但省掉了推导雅可比的人力成本——在快速原型开发阶段很有价值。

一、数值稳定性——协方差矩阵的保卫战

在教科书上，卡尔曼滤波完美无缺。但在 32 位浮点数的世界里，魔鬼藏在细节中。

问题 1：P 矩阵失去对称性

反复执行 \(P = (I-KH)P\) 后，浮点舍入会让 P 不再精确对称。解法很简单：

/* 每次更新后强制对称化 */
for (int i = 0; i < n; i++)
    for (int j = i+1; j < n; j++)
        kf.P[i][j] = kf.P[j][i] = 0.5f * (kf.P[i][j] + kf.P[j][i]);

问题 2：P 矩阵变为负定

更严重的问题是 P 的对角元素可能变负——这意味着"方差为负"，物理上毫无意义。原因通常是 \((I-KH)P\) 这个简化形式的数值误差累积。

Joseph 形式——推荐的更新方程：

$$\mathbf{P} = (\mathbf{I}-\mathbf{K}\mathbf{H})\mathbf{P}(\mathbf{I}-\mathbf{K}\mathbf{H})^T + \mathbf{K}\mathbf{R}\mathbf{K}^T$$

数学上等价，但数值上保证了 P 的正半定性。代价是额外一次矩阵乘法。

问题 3：P 矩阵爆炸（发散）

如果 Q 设得太小，滤波器过于相信模型，拒绝接受新的测量信息，P 越来越小，K 接近零，然后如果真实系统突然发生变化（比如一阵风），滤波器完全跟不上——这叫"滤波器锁死"。

二、诊断方法——新息序列分析

新息（Innovation）\(\nu_k = z_k - H\hat{x}_{k|k-1}\) 是判断滤波器是否健康的最佳指标。对于调参正确的滤波器：

  • 新息序列均值应该接近零（无偏）
  • 新息方差应该和 \(S = HPH^T + R\) 一致
  • 归一化新息平方（NIS）：\(\nu^T S^{-1} \nu\) 应该服从 \(\chi^2(m)\) 分布，均值等于观测维数 m
  • 新息不应该有明显的自相关——如果有，说明 Q 或模型不对

三、系统化调参——飞控工程师的实战流程

在实际飞控开发中（PX4、ArduPilot），调参不是"拍脑袋猜"——而是一套可重复的工程流程。MIT 16.322 课程和工业界的经验总结为以下四步：

Step 1：确定 R（测量噪声）——让传感器告诉你

R 是最容易确定的参数，因为你可以直接测。让传感器静止，采集一段数据，计算方差，就是 R。

  • GPS：静置 10 分钟，记录位置，计算方差 → 通常 \(R \approx 2 \sim 5 \, \text{m}^2\)
  • 气压计：静置 5 分钟，计算高度方差 → 通常 \(R \approx 0.1 \sim 0.5 \, \text{m}^2\)
  • IMU：使用 Allan 方差分析（见下节），提取噪声密度和偏差不稳定性
/* 在 MCU 上用 Welford 算法在线计算传感器方差 */
typedef struct {
    int    n;
    float  mean;
    float  M2;    /* 累积方差 */
} Welford_t;

void welford_update(Welford_t *w, float x) {
    w->n++;
    float delta = x - w->mean;
    w->mean += delta / w->n;
    float delta2 = x - w->mean;
    w->M2 += delta * delta2;
}

float welford_variance(const Welford_t *w) {
    return w->n > 1 ? w->M2 / (w->n - 1) : 0.0f;
}

Step 2：初始化 Q（过程噪声）——从传感器噪声推导

Q 没有 R 那么直观，但也不是完全靠猜。对于位置-速度模型，Q 来自加速度计噪声的积分。连续白噪声离散化公式：

$$Q_d = \int_0^{\Delta t} F(\tau) \cdot G \cdot q_c \cdot G^T \cdot F(\tau)^T \, d\tau$$

其中 \(q_c\) 是连续时间的功率谱密度。实用近似：

$$q_c \approx (\text{加速度计噪声密度})^2$$

对于 MEMS IMU（如 MPU6050）：噪声密度 ≈ 400μg/√Hz → \(q_c \approx (0.004)^2 = 1.6 \times 10^{-5} \, \text{m}^2/\text{s}^4\)

对于匀速模型（位置+速度），离散化后：

$$Q_d = q_c \begin{bmatrix} \Delta t^3/3 & \Delta t^2/2 \\ \Delta t^2/2 & \Delta t \end{bmatrix}$$

Step 3：用 NIS 在线验证——滤波器的"体温计"

归一化新息平方（Normalized Innovation Squared, NIS）是判断调参是否正确的定量工具：

$$\text{NIS}_k = \nu_k^T S_k^{-1} \nu_k \sim \chi^2(m)$$

其中 \(m\) 是观测维数。正确调参时：

  • \(\mathbb{E}[\text{NIS}] = m\)（观测维数）
  • NIS 持续 \(> m\) → R 太小或 Q 太小（滤波器过于自信）
  • NIS 持续 \(< m\) → R 太大或 Q 太大（滤波器过于保守）
  • 用滑动窗口平均 NIS，和 \(m\) 比较，调整 Q 和 R 直到匹配

Step 4：动态验证——实际机动测试

静态验证通过后，还要做动态测试。做实际机动（转弯、加减速），观察跟踪误差：

  • 如果转弯时估计滞后 → Q 太小，滤波器太相信模型，不愿接受新信息
  • 如果直线飞行时估计抖动 → Q 太大，滤波器太不相信模型，被噪声带着走
  • 如果突然机动后估计长时间不收敛 → P₀ 太小，或 Q 太小导致"锁死"
关键经验：先把 Q 设大一点，让滤波器"活"过来（宁可抖动也不要锁死），然后逐步减小 Q 直到 NIS ≈ m。这就是飞控工程师口中的"从松到紧"调参法。

四、Allan 方差——读懂 IMU 噪声的密码

Allan 方差是 IMU 噪声分析的工业标准方法（IEEE Std 952-1997），也是读懂 IMU 数据手册的钥匙。

基本思想：把传感器数据按不同的平均时间 \(\tau\) 分组，计算各组均值之差的方差。在 log-log 图上：x 轴是平均时间 \(\tau\)，y 轴是 Allan 偏差 \(\sigma(\tau)\)。

不同斜率代表不同的噪声类型：

斜率 噪声类型 物理含义 对 KF 的意义
斜率 = -1/2白噪声 (ARW/VRW)角度/速度随机游走决定 Q 矩阵
斜率 = 0（平坦）偏差不稳定性传感器精度的"地板"IMU 精度的下限
斜率 = +1/2随机游走（偏差漂移）偏差缓慢漂移需要增加偏差状态来估计

常见 IMU 的典型参数（陀螺仪）：

型号 ARW (°/√hr) 偏差不稳定性 (°/hr) 等级 应用
MPU6050≈ 0.3≈ 10消费级玩具、简单平衡车
BMI088≈ 0.09≈ 3工业级无人机、机器人
ADIS16488≈ 0.006≈ 0.3战术级导弹制导、测绘

如何计算 Allan 方差：可以用 Python 的 allantools 库，或者在嵌入式端用 C 实现 log-binning 算法。静置 IMU 采集 1~2 小时数据即可画出完整的 Allan 方差曲线。

五、协方差匹配法——自动化调参

手动调 Q 和 R 虽然有效，但有没有自动化的方法？有。协方差匹配法（Covariance Matching / Autocovariance Method）就是其中之一：

  1. 采集新息序列 \(\{\nu_k\}\)
  2. 计算样本自协方差：\(C_0 = \frac{1}{N}\sum_{k=1}^{N} \nu_k \nu_k^T\)
  3. 理论上，\(C_0\) 应该等于 \(S = HPH^T + R\)
  4. 如果 \(C_0 > S\) → 说明实际新息方差大于模型预测 → 增大 Q（或减小 R）
  5. 如果 \(C_0 < S\) → 说明实际新息方差小于模型预测 → 减小 Q（或增大 R）
  6. 可以用简单的自适应循环自动调整
/* 在线协方差匹配：滑动窗口自适应 Q 调整 */
#define COV_WINDOW 50

typedef struct {
    float innov_buf[COV_WINDOW];
    int   head;
    int   count;
    float sum_sq;
} CovMatch_t;

void covmatch_init(CovMatch_t *cm) {
    memset(cm, 0, sizeof(*cm));
}

/* 每次卡尔曼更新后调用：
 * innov  = 本次新息
 * S      = 本次新息协方差 HPH'+R
 * Q_diag = Q 对角线指针，由此函数自动调整 */
void covmatch_update(CovMatch_t *cm, float innov, float S,
                     float *Q_diag, int n) {
    /* 滑动窗口更新 */
    if (cm->count >= COV_WINDOW)
        cm->sum_sq -= cm->innov_buf[cm->head] *
                      cm->innov_buf[cm->head];
    cm->innov_buf[cm->head] = innov;
    cm->sum_sq += innov * innov;
    cm->head = (cm->head + 1) % COV_WINDOW;
    if (cm->count < COV_WINDOW) cm->count++;

    if (cm->count < COV_WINDOW) return;

    float empirical_S = cm->sum_sq / COV_WINDOW;
    float ratio = empirical_S / S;

    /* ratio > 1 → 实际方差大于理论 → 增大 Q
     * ratio < 1 → 实际方差小于理论 → 减小 Q */
    float alpha = 0.01f;  /* 调整步长，越小越稳 */
    float scale = 1.0f + alpha * (ratio - 1.0f);
    scale = fmaxf(0.5f, fminf(2.0f, scale)); /* 限幅 */

    for (int i = 0; i < n; i++)
        Q_diag[i] *= scale;
}

ARM Cortex-M 简化滤波器示例（1D 温度估计，适合理解核心结构）：

/* kf1d.c — 最小化实现，适合 Cortex-M0+ */
typedef struct {
    float x;    /* 状态估计 */
    float P;    /* 估计方差 */
    float Q;    /* 过程噪声方差 */
    float R;    /* 测量噪声方差 */
} KF1D_t;

void kf1d_predict(KF1D_t *kf) {
    /* 状态不变（温度缓慢变化模型） */
    kf->P += kf->Q;
}

void kf1d_update(KF1D_t *kf, float z) {
    float K = kf->P / (kf->P + kf->R);
    kf->x += K * (z - kf->x);
    kf->P *= (1.0f - K);
}

/* 用法：
 * KF1D_t kf = {.x=25.0, .P=10.0, .Q=0.01, .R=1.0};
 * while(1) {
 *     kf1d_predict(&kf);
 *     float temp = read_adc_temperature();
 *     kf1d_update(&kf, temp);
 *     printf("估计温度: %.2f, 不确定度: %.4f\n", kf.x, kf.P);
 * }
 */

实时性预算参考：

  • 4 维 KF，Cortex-M4F @168MHz：约 5~10μs（包括协方差更新）
  • 9 维 KF，同平台：约 30~50μs
  • 4 维 EKF（含雅可比+三角函数）：约 15~25μs
  • 以上时间都远小于 1ms（1kHz 控制周期），所以卡尔曼滤波在飞控中完全可行

平方根滤波（Square Root Filter）

存储 \(S\) 使得 \(P = SS^T\)，用 Cholesky 更新代替标准 P 更新。

  • 数值稳定性极佳——P 永远正定（因为 \(SS^T\) 天生正定）
  • 代价：实现复杂度增加约 2×，需要 Cholesky 分解和 rank-1 更新
  • 推荐用于：航天级应用、长时间运行（数天/数周）的系统
  • 条件数提升：\(\kappa(S) = \sqrt{\kappa(P)}\)，相当于有效精度翻倍

UD 分解滤波（Bierman Filter）

存储 \(P = UDU^T\)（U 为单位上三角矩阵，D 为对角矩阵）。

  • Bierman 的 UD filter + Thornton 的 MWGS（Modified Weighted Gram-Schmidt）算法
  • 在存储量几乎不增加的情况下保证正定性（U 和 D 共用 \(n(n+1)/2\) 个元素，和上三角存储一样）
  • NASA JPL 在深空探测器导航（旅行者号、卡西尼号）中使用此方法——连续运行数年不发散
  • 比平方根滤波更节省计算量，是嵌入式高可靠场景的首选

二、误差状态卡尔曼滤波（ESKF）——工业界的真正主角

教科书上花大量篇幅讲 EKF，但在真正的飞控代码里（PX4 的 ecl/EKF、ArduPilot 的 AP_NavEKF3），你看到的其实是 ESKF（Error-State Kalman Filter）。这不是巧合——ESKF 在工程上有决定性的优势。

核心思想：大的用非线性算，小的用线性化

ESKF 把状态分成两部分：

  • 标称状态（Nominal State）：用精确的非线性方程传播。比如四元数积分，用的是精确的旋转矩阵，不做任何近似。
  • 误差状态（Error State）：标称状态和真实状态之间的小偏差。因为"小"，所以线性化很准确。

打个比方：你开车去北京，里程表（IMU）一路记录行驶距离——这是标称状态的传播，完全按非线性的实际道路积分。偶尔路过一个路牌（GPS），你发现"差了200米"——这个200米就是误差状态。你只需要对这200米做卡尔曼更新，而不是对整个1000公里重新滤波。

四元数姿态估计中的 ESKF

这是 ESKF 最经典的应用。直接用 EKF 估计四元数有个麻烦：四元数有 4 个分量但只有 3 个自由度（因为 \(\|q\| = 1\) 约束），协方差矩阵会出现奇异性。ESKF 优雅地解决了这个问题：

  1. 标称四元数：通过积分陀螺仪测量精确传播（四元数微分方程，不做近似）
  2. 误差状态：3 维旋转误差向量 \(\delta\boldsymbol{\theta}\)（不是 4D 四元数！）→ 协方差矩阵是 3×3，没有奇异性
  3. 卡尔曼更新：用加速度计/磁力计观测更新 \(\delta\boldsymbol{\theta}\)
  4. 注入校正：\(q \leftarrow q \otimes \begin{bmatrix} 1 \\ \delta\boldsymbol{\theta}/2 \end{bmatrix}\)，然后重置 \(\delta\boldsymbol{\theta} = 0\)

三、UKF——不用算雅可比的妙招

UKF（Unscented Kalman Filter）的核心思想是：与其线性化函数（EKF），不如直接用有代表性的采样点通过非线性函数，然后从输出重建统计量。

具体步骤：

  1. 生成 \(2n+1\) 个 Sigma 点：\(\chi_0 = \mu\)，\(\chi_i = \mu \pm \sqrt{(n+\lambda)P}\)
  2. 每个点通过非线性函数：\(\gamma_i = f(\chi_i)\)
  3. 从输出计算加权均值和协方差

五、超越卡尔曼——因子图优化方法

学完卡尔曼家族，你可能觉得 EKF-SLAM 就是 SLAM 的终极方案。事实上，现代 SLAM 系统早已"毕业"了。

Google Cartographer、ORB-SLAM、VINS-Mono——当今最成功的 SLAM 系统都不用 EKF-SLAM。它们用的是因子图优化（Factor Graph Optimization），借助 iSAM、GTSAM、Ceres Solver 等工具实现。

关键区别在于：

特性卡尔曼滤波因子图优化
处理方式在线、单次遍历——处理完一个时刻就丢弃批处理——保留所有历史状态，可反复优化
回环检测无法处理——过去的状态已经"凝固"天然支持——检测到回环后重新优化整条轨迹
计算复杂度\(O(n^2)\) per step（n = 状态维度）利用稀疏性，增量优化高效
适用场景实时状态估计（飞控、导航）建图、SLAM、后处理

直觉：KF 就像用钢笔写字——写下去就改不了。因子图就像用铅笔——随时可以擦掉重写，发现之前写错了也能回头修正。

在实践中，两者经常配合使用：KF（特别是 ESKF）负责 IMU 高频实时状态估计（飞控需要 400Hz 的姿态），因子图负责低频的地图优化和回环校正。

六、自适应卡尔曼滤波简介

标准 KF 假设 Q 和 R 是已知常数。但实际中噪声会变：GPS 在城市峡谷中精度急剧下降，电机在变速时过程噪声增大。

简单方法：基于新息的自适应

监测新息序列的实际方差，和理论方差 \(S = HPH^T + R\) 比较。如果实际方差明显大于理论值，说明 R 被低估了（或 Q 被低估了），动态调整：

$$\hat{R}_k = \frac{1}{W}\sum_{i=k-W+1}^{k} \nu_i \nu_i^T - HPH^T$$

七、一个优美的数学巧合——KF 与 LQR 的对偶性

MIT 16.322 和 6.011 课程都会讲这个结果，因为它揭示了估计与控制之间的深层联系。

先看两个看似无关的问题：

  • 卡尔曼滤波：从含噪声的观测中估计状态 → 最小化估计误差的协方差
  • LQR 最优控制：计算控制输入使系统跟踪目标 → 最小化跟踪误差的代价函数

它们的核心方程竟然是同一个 Riccati 方程，只是矩阵做了转置！

卡尔曼滤波对应关系LQR 控制
\(F\)（状态转移）↔\(F^T\)
\(H\)（观测矩阵）↔\(B^T\)（控制输入矩阵的转置）
\(Q\)（过程噪声）↔\(Q_{lqr}\)（状态代价矩阵）
\(R\)（测量噪声）↔\(R_{lqr}\)（控制代价矩阵）
\(P\)（误差协方差）↔\(P_{lqr}\)（代价矩阵）
\(K\)（卡尔曼增益）↔\(K_{lqr}\)（反馈增益）

实际意义：如果你已经理解了其中一个，你就自动理解了另一个。

在飞控系统中，这两者常常手拉手出现——这就是 LQG（Linear Quadratic Gaussian） 控制：

传感器数据 → 卡尔曼滤波（最优估计） → LQR 控制（最优控制） → 执行器

分离原理（Separation Principle）告诉我们：最优估计 + 最优控制 = 最优整体设计。你可以独立设计 KF 和 LQR，组合起来仍然是最优的。

重要限制：分离原理只在线性高斯系统中严格成立。对于非线性系统（EKF + 非线性控制），用估计值代替真实状态进行控制（即"确定性等价"原则）只是一种近似，不保证全局最优。但在实践中，这种近似通常工作得很好。

嵌入式开发者笔记

从沙盒到产品的迁移清单：

  1. 用沙盒确定 F、H、Q、R 的初始值
  2. 导出 C 代码，集成到你的 MCU 工程
  3. 在真实硬件上采集传感器数据，用 Welford 算法计算 R（参见第二章）
  4. 在线调 Q：太小跟不上 → 增大；估计抖动 → 减小
  5. 监测新息序列和 NIS（参见第七章），确保滤波器健康
  6. 考虑用 Joseph 形式替换标准 P 更新以增强稳定性
  7. 如果性能不够，用上三角存储 P 并展开矩阵运算
  8. 在 release 模式下做一次运行时间测量，确保不超时

从沙盒到产品的真实案例——一个无人机定高滤波器的开发流程：

  1. 在沙盒中验证滤波器结构和初始参数：选择"无人机定高"预设，用正弦信号模拟升降，观察 KF 跟踪效果。调整 Q 和 R 直到跟踪误差和响应速度令人满意。
  2. 导出 C 代码，集成到 MCU 工程：点击"导出 C 代码"，将生成的 kf_init()、kf_predict()、kf_update() 复制到你的 STM32 工程中。
  3. 在硬件上采集真实传感器数据：让无人机静置和简单升降，用串口将气压计和 IMU 数据以 CSV 格式输出到 SD 卡。
  4. 在沙盒中重放真实数据：切换到"CSV 数据"标签页，上传刚采集的 CSV，用同样的 F/H/Q/R 运行。
  5. 对比真实数据和仿真数据的滤波效果：如果真实数据的跟踪效果比仿真差很多，说明传感器噪声模型需要修正。
  6. 微调 Q 和 R，用 NIS 验证：监测 NIS 是否接近观测维数 m。勾选 Mahalanobis Gate 可以自动剔除偶发的 GPS 多路径干扰。
  7. 将最终参数写回固件：更新 kf_init() 中的 Q 和 R 矩阵值。
  8. 在实际运行中监测 NIS，必要时在线自适应：部署后持续记录 NIS，如果环境变化（如从室外飞到室内），考虑启用自适应 Q 调整（参见第八章）。
